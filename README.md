# Codifykit website

The marketing site for Codifykit: a static Next.js site with one small server function (Kitto's AI chat), built to run on **Cloudflare Pages**.

## Run it locally

```bash
npm install
npm run dev          # http://localhost:3000 (Kitto's chat needs `npm start`, below)
npm run build        # writes the static site to /out
npm start            # serves /out + the Kitto function with Cloudflare's local runtime
```

For the chat to work locally, create `.dev.vars` (never commit it):

```
ANTHROPIC_API_KEY=sk-ant-...
```

## Deploy to Cloudflare Pages

### Option A: connect the GitHub repo (recommended)

1. Cloudflare dashboard → **Workers & Pages** → **Create** → **Pages** → **Connect to Git** → pick `codifykit`.
2. Build settings:
   - Framework preset: **None**
   - Build command: `npm run build`
   - Build output directory: `out`
   - Environment variable: `NODE_VERSION` = `22`
3. **Settings → Variables and secrets**:
   - `ANTHROPIC_API_KEY` (type **Secret**): your Claude API key, from console.anthropic.com.
   - `NEXT_PUBLIC_SITE_URL` (plain text): your final address, e.g. `https://codifykit.com`. It's used for the sitemap, social previews and SEO tags.
   - Optional: `KITTO_MODEL` to use a different Claude model. The default is `claude-opus-5-5`.
4. **Settings → Runtime → Compatibility flags**: add `nodejs_compat`. `wrangler.toml` already sets this.
5. Deploy. Every push to the branch redeploys.
6. Add your domain under **Custom domains**.

### Option B: deploy from your computer

```bash
npx wrangler login
npm run deploy                                      # builds and uploads /out + /functions
npx wrangler pages secret put ANTHROPIC_API_KEY --project-name codifykit
```

### Optional: stronger rate limiting for Kitto

By default Kitto allows 20 messages per visitor every 10 minutes, counted per Cloudflare edge location. To count across all locations, create a KV namespace and bind it as `RATE_LIMIT` (Settings → Bindings → KV namespace).

## 3D models

`/work/web` uses a real MacBook model (`public/models/laptop.glb`, from the MIT-licensed pmndrs/examples repo; see `public/models/CREDITS.md`).
`/work/posters` uses a phone modelled in code until you add a real one:

1. Get a phone GLB you're allowed to use commercially (CC0, CC-BY with credit, or bought), ideally without brand logos.
2. Make sure the screen's material is named `screen` or `display` (rename it in Blender if needed).
3. Save it as `public/models/phone.glb` and set `"phone": "/models/phone.glb"` in `public/models/manifest.json`.
4. Add a line to `public/models/CREDITS.md`.

## Replacing placeholders with real work

Anything in `content/*.json` that starts with `[PLACEHOLDER` or `[FILL IN` shows on the site with a dashed outline, so it's easy to spot. The placeholder images in `public/work/` are generated by `npm run placeholders`; each one has a small "PLACEHOLDER" tag.

To add real work:

1. Put files in `public/work/web/`, `public/work/apps/`, `public/work/posters/` and `public/work/reels/` (sizes are in `docs/07-assets.md` of the handoff pack).
2. Update the matching JSON file: titles, clients, years and image paths. Use `null` for anything you can't share; the site hides it.
3. Reels in the hero wheel: set `video` on a card in `content/wheel-cards.json` to a muted 9:16 MP4. Cards near the top play it automatically.
4. Team photo: add `public/images/team-pill.webp` and swap the placeholder in `src/components/sections/Story.tsx` and `src/app/about/page.tsx`.
5. Delete the placeholder files you no longer use.

Never add clients, numbers or testimonials you don't have permission to use.
